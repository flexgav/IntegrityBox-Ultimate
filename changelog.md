#### 🚀 IntegrityBox Ultimate v43.6

Many important improvements and optimizations: keybox sanitizing and normalization, missing properties added directly to the GMS check process, improved disabling of ROM built-in spoofing, device RKP key issuance by every available method, HMA template import for any manager version, and an optimized WebUI that runs commands in the background.

- **PKCS#8 keys in keyboxes**: some sources store the private key as `BEGIN PRIVATE KEY` (PKCS#8). None of the supported backends (TEESimulator, TEESimulator-RS, Tricky Store and its forks, OhMyKeymint) reads a key in this form, so with such a keybox they could not sign any attestation and Play Integrity returned no verdict at all. The catalog rebuild now writes the key in the usual form: EC as `EC PRIVATE KEY`, RSA as `RSA PRIVATE KEY`. The key itself does not change; encrypted and unknown keys stay as they were.
- **Usual layout first**: a keybox written in one line is laid out before anything else, with every certificate and key marker on a line of its own. It then goes through the key conversion and the date and revocation checks like any other keybox.
- **Comments inside certificates**: some publishers put comments right inside certificates, which broke the date and revocation checks and could make OhMyKeymint reject the key. Comments are removed before any check.
- **Expired root certificate**: a self-signed root that signs the chain is now treated as a trust anchor, and its own expiry no longer marks the whole keybox expired.
- **Revocation status in Keybox Loader**: after the recheck during key selection the catalog statuses are updated, so a checked keybox no longer shows as unchecked. The Google revocation list is downloaded once per run and shared by the sync, the key selection and RKP. The UNCHECKED status is renamed UNDETERMINED: it means there is not enough data for a verdict.
- **Revocation list retries**: a failed download is retried up to five times, with two seconds between attempts. If the list remains unavailable, unconfirmed statuses stay "UNDETERMINED" and automatic selection relies on publication dates.
- **Backend switch**: moving the keybox to another backend failed with a validation error. Fixed; the source, the slot and the manual choice are kept.
- **Older backend versions**: most pool keys are RKP keys, which hold only an EC key and no RSA key. TEESimulator v4 before build 51 and OhMyKeymint before 1.2.5 cannot work with such keys, so attestation failed once an RKP key was applied. The backend driver now checks the backend version before writing a key. With such a version automatic selection takes a keybox with an RSA key, while a manually chosen RKP key and the device RKP key are not written. Keybox Loader and the Action output ask to update the backend. Tricky Store and its forks, TEESimulator v1-v3 and TEESimulator-RS work with such keys in every version.
- **Fewer repeated checks**: normalization and checks run when the pool is built and are not repeated during selection and apply, except for one check right before the write.
- **Device RKP tries every method**: a missing system RKP component used to block issuance entirely, although the native methods for the processor may work without it. Now it rules out only the method that depends on it; the module tries the others and turns generation off only when no method is eligible or the device rejects every method in five attempts in a row. Network errors, Google refusals and a busy device keep generation enabled.
- **Reason for a failed issuance**: Keybox Loader shows what got in the way: no connection to Google, Google did not issue the key, or a temporary failure on the device. In these cases generation stays enabled for another attempt.
- **Damaged device RKP keys**: when the phone's secure hardware does not create the key request (usually after flashing through EDL or a failed update), Keybox Loader shows this reason. The check runs on the device without contacting the server.- **Properties the device lacks**: the profile sets `ro.board.first_api_level` and `ro.product.first_api_level`, but the module could only replace a property the device already has. On devices and ROMs without `ro.board.first_api_level` the profile value never reached the Play Integrity check; the PlayIntegrityFork author measured 3 of 23 Canary profiles passing in this case and 15 of 23 with the property. The module now adds the missing property with the profile value to the Play Integrity check process (DroidGuard) only. The system and other apps still do not see it, so detectors find nothing new. Where the device has the property, it is replaced as before.
- **WebUI without freezes**: commands run in the background through `ksu.spawn`, so the interface stays responsive during an operation. Where the manager can read files directly (KernelSU, SukiSU, WebUI X), files are read without starting a shell; elsewhere the previous way is used.
- **Faster interface**: the basic parameters (language, root access, backend data) are determined once in the main window, and every submodule takes them from there. System queries run as one batch in the background; the app lists of all Android users, for example, arrive in one request. The scripts of the slowest pages (ROM Props, Fingerprint Selector, Hide Suspicious Files) were rewritten. As a result the module interface is noticeably faster.
- **ROM spoofing through Android settings**: crDroid, Evolution X, PixelOS and similar ROMs turn on their built-in PIF spoofing and built-in TrickyStore through Android settings. The module turns these settings off for every user, keeps the previous values and restores them when the module is removed.
- **LineageOS updates**: "Spoof Lineage Props" also removed the properties the LineageOS updater uses to find new builds. These three properties now stay.
- **HMA template for any manager version**: the HideMyApplist template was not applied to HMA-OSS oss-175 and newer until the manager had created its own config. The module now takes the config format from the installed app (HMA, HMAL, HMA-OSS), so the template applies to any version; hide sets, settings and app assignments are kept.
- **HMA import validation**: hide sets, settings sets and app assignments must survive conversion to the installed app's format. If a required field is lost, import stops with an error and keeps the existing configuration.
- **Report**: shows HMA assignments with the number of applied templates and the app spoofing state. Hide lists are not included.
- **Fallback mirror**: when `raw.githubusercontent.com` is blocked, module downloads go through the jsDelivr mirror.
- **WebUI on Magisk**: after a manual Action on Magisk the module WebUI opens in KsuWebUIStandalone or WebUI X when one of them is installed.
- **Terminal language**: the scripts' language cache was reset by any change of Android settings, and the script queried the system language again, adding up to a second to every start. The cache is now reset only when the system language or the module language changes.
